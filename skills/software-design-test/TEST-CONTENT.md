# 测试内容清单 / What to Test

> **这是"测什么"的主清单。** 每个类别都给出：检查项、怎么看（真实操作）、判据（带规范编号或经验阈值）。
> 用法：先做 §0 的十分钟快扫，再按需要逐类展开；每条结论都要能指到画面上的具体位置。
> The master checklist of *what* to test: item, how to check by hand, and the criterion (with the
> WCAG clause or platform guideline where one exists).

**你提到的三项在本清单里的位置**：界面大小 → §1 · 鼠标速度与指针 → §2 · 工具栏 → §4。

---

## 0. 十分钟快扫 / The ten-minute sweep

每次会话开始先跑这十项，便宜且命中率高：

1. 打开应用：默认窗口是否**完整可见**（不超出屏幕、不钻到菜单栏/Dock 下面）。
2. 把窗口缩到最小可用尺寸：主按钮还在吗？文字被裁了吗？出现横向滚动条了吗？
3. 放大到系统缩放 200%：内容是否溢出/重叠。
4. 只动鼠标走一遍主任务：有没有必须悬停才知道的地方。
5. 只用键盘走一遍主任务：Tab 能不能走到底，焦点看得见吗。
6. 记录**指针总行程**：主任务需要移动的累计距离与最远距离。
7. 扫一眼工具栏：每个图标不看提示词能不能看懂；有没有文字或 tooltip。
8. 点一个会耗时 >1 秒的操作：有没有加载反馈；能不能取消。
9. 故意输错：错误提示说人话吗，指出位置了吗，给了下一步吗。
10. 切到深色模式、换系统字号，各看一眼。

> 快扫只用来找"一眼就能看出"的问题；每条都要落盘成 finding，别留在脑子里。

## 1. 窗口与界面尺寸 / Window and screen-size usability

**核心问题：这个界面在真实用户的屏幕上"装得下、看得清、点得到"吗？**

| 检查项 | 怎么看 |
| --- | --- |
| 默认窗口大小合理 | 首次打开是否完整可见、不超出屏幕、不遮挡系统栏；内容是否需要在默认尺寸下横向滚动 |
| 最小尺寸可用 | 拖到最小：主操作按钮、主输入框、主列表是否仍完整可用；有无裁切或重叠 |
| 最小尺寸下限被尊重 | 是否设置了一个"再小就不能用"的最小尺寸（而不是无限缩小到不可用） |
| 大尺寸不散架 | 最大化/全屏：内容是否被无意义拉伸，行宽是否过长（正文超过 ~100 字符就难读） |
| 分屏与平铺 | macOS Split View / Windows Snap / iPad Split View、Slide Over：布局是否正确，能否在窄栏里完成主任务 |
| 屏幕缩放 | 系统缩放 125% / 150% / 200%：文字与控件按比例放大后不重叠、不裁切、不溢出（WCAG 1.4.4 文本可放大到 200%） |
| 回流 Reflow | 在等价于 320 CSS px 宽时，主流程不需要横向滚动（WCAG 1.4.10） |
| 窗口记忆 | 关闭再打开，位置、大小、最大化状态、分栏宽度是否被记住 |
| 多显示器 | 拖到第二块屏、拔掉外接屏后：窗口是否可达（不出现"跑到屏幕外找不回来"） |
| 全屏与还原 | 进出全屏不丢状态；全屏下系统栏隐藏后仍知道在哪 |
| 内容密度 | 空白过多（浪费屏幕）或过少（拥挤）；信息层级在大屏上是否重新组织 |
| 长内容 | 长列表/长文本在窗口变小时的换行、省略、滚动策略是否一致且可预期 |
| 对话框尺寸 | 弹窗是否过大（超出屏幕）或过小（内容被裁）；弹窗是否可缩放或自适应 |
| 触屏尺寸 | iPhone/iPad：内容是否在安全区内（避开刘海/圆角/Home 指示条），横竖屏切换不丢状态 |

**判据**：能完成主流程 + 不裁切 + 不重叠 + 不用横向滚动 + 记住用户调整过的尺寸。
标准参考：WCAG 1.4.4（放大 200%）、1.4.10（320 CSS px 回流）。

## 2. 鼠标速度与指针 / Pointer dynamics and speed

**核心问题：完成这件事需要"跑多远、动多准、等多久"？**

| 检查项 | 怎么看 | 判据 / 经验值 |
| --- | --- | --- |
| 指针总行程 | 走一遍主任务，在录屏里量指针路径总长与最远两点距离 | 常用动作越近越好（Fitts 定律：时间 ∝ 距离/目标宽度）；主任务要在屏幕内"局部"完成 |
| 精细操作要求 | 是否要求像素级对齐（手动拖分隔条、对齐到 1px、拖到窄热区） | 不应要求"慢速微调"才能完成；拖拽要有吸附/对齐辅助 |
| 双击速度 | 把系统"双击速度"调到最慢与最快各试一次（macOS：系统设置 → 鼠标/触控板，或辅助功能里的连按速度） | 应用必须尊重系统设置，不能自定一套更快的双击窗口 |
| 悬停延迟 | 悬停工具提示多快出现、是否必须悬停才能发现功能 | 提示 300–500ms 内出现；**功能不允许只靠悬停才能发现**（触屏与键盘用户不可用） |
| 拖拽 | 拖拽过程有反馈吗？能取消（Esc）吗？有非拖拽替代吗？ | WCAG 2.5.7 拖拽动作需提供单指针非拖拽替代 |
| 拖拽距离与容差 | 长距离拖拽（跨窗口、跨屏）、拖到边缘、拖到无效区域 | 无效区域要给出"为什么不行"的反馈；不丢数据 |
| 光标反馈 | 进入可拖拽/可缩放/可文本选择区域时，光标形状是否即时变化 | 形状变化需在 ≤100ms 内出现，且与可做动作一致 |
| 指针速度与加速度 | 应用是否修改系统指针速度/加速度；是否自带"慢速模式" | 不应悄悄改变系统设置；若提供，必须显式且可复位 |
| 滚轮与触控板 | 滚动速度、惯性、横向滚动、精确（像素级）滚动 | 与系统设置一致；长页面可加速，但不要"一滚到底" |
| 命中区一致性 | 目标边缘外 2px、图标之间的缝隙、图标外框 | 热区必须与视觉一致；热区不小于目标本身 |
| 误触保护 | 相邻的危险操作（删除/覆盖/退出）间距 | 危险操作间距更大 + 二次确认 + 可撤销 |
| 指针穿越干扰 | 鼠标从 A 移动到 B 时，路径上是否会误触发悬停菜单/展开面板 | 悬停菜单应有延迟与容错三角，不应"路过就弹" |

**快速测量法**：开录屏 → 操作 → 在录屏里取"起点帧"和"终点帧"，用屏幕宽度做尺子估算行程
（例如 1920 px 屏上走了 1.5 屏 ≈ 2900 px 的指针移动）。**不需要任何自动化工具。**

> How to measure without tooling: record the screen, then read the start and end positions off two
> frames and use the screen width as the ruler.

## 3. 目标尺寸与间距 / Target size and spacing

| 检查项 | 判据 |
| --- | --- |
| 触控目标最小尺寸 | WCAG 2.5.8（AA）：24×24 CSS px；WCAG 2.5.5（AAA）：44×44；Apple HIG 触控：44×44 pt；Material：48×48 dp |
| 桌面紧凑控件 | 图标按钮的**命中区**至少与 24×24 等价，且大于图标视觉边界 |
| 相邻目标间距 | 目标之间至少留出可辨间隙（避免"想点 A 点到 B"） |
| 滚动条抓取区 | 细滚动条（macOS 悬浮滚动条）是否仍能抓到；有无键盘/触控板替代 |
| 危险操作 | 删除/覆盖等目标不与常用操作紧邻 |
| 边缘手势 | 触屏/触控板边缘手势是否与系统级手势冲突 |

## 4. 工具栏与菜单 / Toolbar and menus

| 检查项 | 怎么看 |
| --- | --- |
| 图标可识别 | 不看 tooltip 能否理解含义；陌生图标是否有文字标签 |
| 提示可用 | 悬停是否有 tooltip；tooltip 是否包含名称 + 快捷键 |
| 分组与顺序 | 是否按使用频率/功能逻辑分组；常用命令是否一级可达（不藏进二级菜单或设置） |
| 密度与留白 | 是否过挤（图标贴在一起）或过空；与内容区比例是否合理 |
| 溢出行为 | 窗口变窄时，工具栏是自适应收纳（» 溢出菜单）还是直接消失 |
| 状态可见 | 激活/选中/禁用态是否清晰；禁用能否知道原因 |
| 一致性 | 工具栏、菜单、右键菜单、快捷键提示是否指同一个命令、同一套命名 |
| 可定制 | 若支持自定义：能否拖动、能否恢复默认、重启后是否记住 |
| 读取顺序 | 从左到右的阅读顺序是否符合"高频在前"；是否因图标宽窄导致视觉错位 |
| 菜单可用性 | 文字不截断、不歧义；子菜单打开方向正确（不超出屏幕）；键盘可导航 |
| 触屏适配 | 工具栏在窄屏是否折叠为底部/更多菜单；命中区是否 ≥44pt |

**判据**：一个新用户在 **10 秒内**能找到"导出/保存/搜索"这类主命令。

## 5. 文字与排版 / Text legibility

| 检查项 | 判据 |
| --- | --- |
| 对比度 | 正文 ≥ 4.5:1，大字（≥18pt 或 14pt 粗体）≥ 3:1（WCAG 1.4.3）；非文本元素 ≥ 3:1（1.4.11） |
| 默认字号 | 与平台惯例一致，长文本阅读不费力；不靠用户自己放大 |
| 长文本处理 | 截断策略一致（尾部省略/中间省略/换行）；标题截断不丢关键信息 |
| 混排 | 中英数混排、emoji、RTL 文本不破版；数字与单位对齐 |
| 放大 | 系统字号/动态字体放大后不重叠、不裁切（WCAG 1.4.4） |
| 深色模式 | 对比度仍达标；纯黑背景上的细字与阴影是否"糊" |
| 行距字距 | 行高足够（约 1.4–1.6 倍字号），段间距清晰 |
| 占位符 | 占位符不能替代标签（占位符一消失就不知道填什么） |

## 6. 布局与层级 / Layout and hierarchy

| 检查项 | 怎么看 |
| --- | --- |
| 主次分明 | 一屏是否只有一个主操作；次要操作是否视觉降级 |
| 遮挡 | 弹窗/抽屉/浮层是否遮住关键信息；提示是否被裁或被遮挡（WCAG 2.4.11 焦点不被遮挡） |
| 层叠顺序 | 菜单、下拉、提示之间是否互相遮挡或穿透 |
| 对齐与网格 | 元素是否按网格对齐；间距是否一致（同类元素同间距） |
| 滚动容器 | 是否存在嵌套滚动、滚动陷阱、滚动条与内容不同步 |
| 空/加载/错误态 | 三种状态的布局是否都设计过（不是只做"有数据"的样子） |
| 视觉噪音 | 边框/阴影/分隔线是否过多，是否用颜色替代层级 |

---

## 7. 反馈与状态 / Feedback and state

| 检查项 | 判据 |
| --- | --- |
| 即时反馈 | 操作后 ≤0.1s 有可见响应；≤1s 不打断思路；>1s 要有进度指示；>10s 要能取消（Nielsen 三个响应时限） |
| 加载 | 有加载态；长任务有进度与可取消；无"白屏假死" |
| 结果提示 | 成功/失败提示可读、可关闭、不遮挡后续操作 |
| 状态持久 | 切换页面/标签、重启应用后，关键状态是否保留 |
| 焦点可见 | 键盘操作时焦点位置始终可见（WCAG 2.4.7） |
| 状态齐全 | 默认/悬停/按下/选中/禁用/忙碌 六态是否都有可见样式 |

---

## 8. 效率与流程 / Efficiency and flow

| 检查项 | 怎么看 |
| --- | --- |
| 步数 | 主任务实际步数 vs 理论最少步数；多出来的步骤是否有理由 |
| 重复输入 | 是否要求重复填写已知信息（WCAG 3.3.7 冗余输入） |
| 默认值 | 默认值是否是常见选择（能不填就不填） |
| 批量 | 批量选择、批量操作、全选/反选；批量失败时的部分成功提示 |
| 撤销重做 | 关键操作可撤销；撤销范围明确 |
| 双路径一致 | 鼠标路径与快捷键路径结果一致（三级模式 L3 专项） |
| 帮助就地 | 需要帮助时能否就地找到（WCAG 3.2.6 一致帮助） |

## 9. 键盘与焦点 / Keyboard and focus

见 `observed-ui-test` 的 LEVELS.md 与 `HEURISTICS.md` §F，核心项：

Tab 顺序与视觉顺序一致 · 焦点环清晰可见 · 无键盘陷阱（WCAG 2.1.2）· 焦点关闭弹窗后回到触发控件 ·
单字符快捷键可关闭或重映射（WCAG 2.1.4）· 快捷键不与系统冲突 · 组合控件（菜单/树/标签页）方向键可用。

---

## 10. 可访问性 / Accessibility

屏幕阅读器标签/角色/状态 · 仅键盘可用（2.1.1）· 颜色不作为唯一信息载体（1.4.1）·
动效可关（prefers-reduced-motion）· 触屏手势有替代 · 动态字体与高对比度模式下可用 ·
表单错误被朗读且指出字段。

---

## 11. 性能与响应 / Performance and responsiveness

启动时间 · 首屏可用时间 · 滚动帧率（目测卡顿与掉帧）· 输入延迟（打字、拖拽跟手度）·
大文件/大列表/大图片 · 长时运行（内存泄漏、超时：用"通宵巡游"）· 离线与弱网 · 后台任务对前台的影响。

---

## 12. 错误与恢复 / Errors and recovery

错误信息说人话、指出位置、给出下一步 · 出错不丢数据（草稿、自动保存）· 崩溃后能否恢复 ·
破坏性操作有确认且可撤销 · 超时/断网时的行为明确 · 不把内部错误码直接抛给用户（除非可复制给支持）。

---

## 13. 数据与输入 / Data and input

空输入 · 超长输入 · 特殊字符与 emoji · 非拉丁文 · 粘贴表格与多行文本 · 前后空格 ·
中文/日文输入法组合期不误提交 · 校验时机（即时 vs 提交）一致 · 复制粘贴格式往返不丢内容 ·
数字格式与本地化（千分位、小数点）· 时间与时区显示。

---

## 14. 跨设备一致性 / Cross-device consistency

同一功能在 macOS / Windows / iPhone / iPad 上的位置、命名、行为是否一致 ·
是否遵循各平台惯例（窗口控制位置、右键菜单、手势、返回逻辑）· 同步状态与冲突提示 ·
外接键鼠与纯触控下的可达性差异。

---

## 15. 视觉打磨 / Visual polish（S4 级，别挤占 S1/S2 的时间）

图标风格统一 · 像素对齐与描边一致性 · 圆角/阴影/分隔线体系 · 动效时长与曲线（避免弹跳过度）·
文案统一（"保存/应用"不混用）· 加载占位与骨架屏的一致性。

## 用法提示 / How to use this file

1. 会话开始时把本清单的类别抄进 `content.md`（`session.mjs init` 已生成骨架）。
2. 每确认一类，在 `content.md` 里写结论（通过 / 违反 / 未验证）+ 证据文件 + 检查项数。
3. 每条违反落盘成 finding，并带上 `content`（类别）与 `criteria`（判据）两个字段，
   报告会按**测试内容**聚合，直接告诉你"问题集中在哪一类"。
